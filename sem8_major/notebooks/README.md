# notebooks/ — Kaggle notebooks

Project notebook: **`yaduvxnshi/authentiscan-a2-gpu-smoke-and-calibration`** (was
`notebook322addb147`; the slug changed when the title was set). Private; CIFAKE attached;
GPU and Internet enabled; `phase_a2_smoke.ipynb` pushed as version 2 on 20 Aug 2026 via the
Kaggle REST API. Push further versions the same way — the CLI's token auth does not work,
the REST endpoint `POST /api/v1/kernels/push` does, and the push payload must always repeat
`datasetDataSources` or the CIFAKE attachment is dropped.

Code transport: the notebook clones the private GitHub repo
`rohityaduvxnshi/sm7` using a Kaggle Secret named `GITHUB_PAT` (Add-ons → Secrets;
fine-grained token with read access to that repo). After the first setup, later code changes
reach Kaggle automatically — the clone cell falls through to `git pull`.

One thin notebook per session (A3, A5) or per phase (A2, A4), generated by the scripts in this
directory: install the extras (Kaggle ships torch/torchvision - never upgrade them), clone the
repo, autodetect the dataset mounts, call the CLI in `code/`. Logic lives in `code/`, not in
cells, so runs stay reproducible. CIFAKE (`birdy654/cifake-real-and-ai-generated-synthetic-images`)
mounts at `/kaggle/input/datasets/<owner>/<slug>` in batch runs (the classic
`/kaggle/input/<slug>` was seen only in the 19 Aug interactive session), so the notebooks walk
`/kaggle/input` for the folder holding `train/REAL` and pass it as `--data-root`. Every result
comes back as a zip from the Output tab and is merged with `code/merge_runs.py`, never retyped.

**A3 sessions** (`phase_a3_s1..s8.ipynb`, generated by `make_a3_notebook.py`): one notebook
per training session, slug `authentiscan-a3-session-<N>`; each output holds that session's
run dirs with `best.pt` and `config_used.yaml`.

**A4** (`phase_a4_crossgen_gradcam.ipynb`, generated by `make_a4_notebook.py`, 4 Sep 2026):
evaluation only — cross-generator sweep + Grad-CAM galleries. It attaches CIFAKE,
`yangsangtai/tiny-genimage` and the eight A3 session outputs as *kernel* data sources, so no
checkpoint is ever uploaded; cell 2 autodetects all mounts and asserts every id in
`results/canonical_runs.txt` is present. Returns `results_a4.zip`: merge `crossgen.csv` with
`python code/merge_runs.py <path>/crossgen.csv --kind crossgen`, then copy
`genimage_verification.csv`, `gradcam_shared_list.txt`, `gradcam_correct/`, the
`<run_id>/genimage_*/` dirs and `figures/gradcam/` into the repo.

**A5 sessions** (`phase_a5_s9.ipynb`, `phase_a5_s10.ipynb`, generated by
`make_a3_notebook.py --session 9|10`, 15 Oct 2026): the three ResNet50-ft ablations
(`resnet50_ft_noaug`, then `resnet50_ft_res64` + `resnet50_ft_res128`), slug
`authentiscan-a5-session-<N>`, same T4-only rule and round-trip as A3. From these sessions
on, cell 4 passes `--time-budget-min` so a run stops cleanly at its budget
(`stop_reason=time_budget`) instead of being killed at the 12 h cap. Returns
`results_a5_s<N>.zip`; merge with `merge_runs.py`, copy the run dirs in, then rerun
`make_tables.py` (t6_ablations appears automatically).

`reference_thirdparty_y5cy5c_keras_cifake.ipynb` is **someone else's public notebook**
(Kaggle user y5cy5c), pulled 19 Aug 2026 as a reference only: a Keras/keras_tuner small-CNN
example on CIFAKE. Do not copy code or numbers from it — different stack (Keras vs our
PyTorch/timm), and it validates on the official test set, which our plan forbids.
